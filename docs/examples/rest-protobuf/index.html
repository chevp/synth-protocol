REST + Protobuf Hybrid

Kompakte Binary-Payloads ohne gRPC-Infrastruktur

Warum REST + Protobuf?

  • Kein Proxy nötig - Direkter HTTP-Aufruf zum Server
  • Bekannte REST-Semantik - GET, POST, PUT, DELETE wie gewohnt
  • Kompakte Payloads - ~30-50% kleiner als JSON
  • Typsicherheit - Generierte Klassen aus .proto Dateien
  • Einfache Migration - Bestehende REST-APIs schrittweise umstellen

Implementierung

// Browser-Client mit protobuf.js

// 1. Proto-Definition laden (oder als generierte JS-Datei)
const root = await protobuf.load('rest-protobuf-example.proto');
const Project = root.lookupType('synth.example.Project');
const CreateProjectRequest = root.lookupType('synth.example.CreateProjectRequest');

// 2. Request mit Protobuf-Payload senden
async function createProject(data) {
    // Objekt zu Protobuf serialisieren
    const message = CreateProjectRequest.create(data);
    const buffer = CreateProjectRequest.encode(message).finish();

    const response = await fetch('/api/projects', {
        method: 'POST',
        headers: {
            'Content-Type': 'application/x-protobuf',
            'Accept': 'application/x-protobuf'
        },
        body: buffer
    });

    // Protobuf Response dekodieren
    const responseBuffer = await response.arrayBuffer();
    const decoded = CreateProjectResponse.decode(new Uint8Array(responseBuffer));

    return decoded.toJSON();
}

// 3. Oder JSON anfordern (Server entscheidet via Accept-Header)
async function getProjectAsJson(id) {
    const response = await fetch(`/api/projects/${id}`, {
        headers: { 'Accept': 'application/json' }
    });
    return response.json();
}
// Java Spring Boot Controller mit Protobuf Support

@RestController
@RequestMapping("/api")
public class ProjectController {

    // Protobuf HTTP Message Converter registrieren
    @Bean
    public ProtobufHttpMessageConverter protobufHttpMessageConverter() {
        return new ProtobufHttpMessageConverter();
    }

    // GET mit Content Negotiation (JSON oder Protobuf)
    @GetMapping(value = "/projects/{id}",
                produces = { "application/x-protobuf", "application/json" })
    public Project getProject(@PathVariable String id) {
        return projectService.findById(id);
    }

    // POST mit Protobuf Request Body
    @PostMapping(value = "/projects",
                 consumes = "application/x-protobuf",
                 produces = "application/x-protobuf")
    public CreateProjectResponse createProject(
            @RequestBody CreateProjectRequest request) {

        Project project = projectService.create(
            request.getName(),
            request.getDescription(),
            request.getTagIdsList()
        );

        return CreateProjectResponse.newBuilder()
            .setProject(project)
            .build();
    }

    // Endpoint der beides akzeptiert
    @PostMapping(value = "/projects/flexible",
                 consumes = { "application/x-protobuf", "application/json" },
                 produces = { "application/x-protobuf", "application/json" })
    public CreateProjectResponse createFlexible(
            @RequestBody CreateProjectRequest request) {
        // Gleiche Logik - Spring handelt Serialisierung automatisch
        return createProject(request);
    }
}

Vorteile dieses Ansatzes

Proxy Nicht nötig - Direkter HTTP-Aufruf
Migration Schrittweise möglich - einzelne Endpoints umstellen
Debugging JSON-Fallback für Browser DevTools
Caching Standard HTTP-Caching funktioniert
Load Balancing Jeder HTTP Load Balancer funktioniert
