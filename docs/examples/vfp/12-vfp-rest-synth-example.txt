================================================================================
VFP REST - SYNTH PROJECT EXAMPLE
================================================================================

Dieses Beispiel zeigt wie ein Synth Projekt (01-basic-example.synth.xml)
über VFP REST API erstellt und bearbeitet wird.

Phase 1: Authoritative Scene Setup (HTTP REST)
Phase 2: Live Events (WebSocket Realtime)


================================================================================
PHASE 1: AUTHORITATIVE SCENE SETUP
================================================================================

Das vollständige Projekt wird initial über HTTP REST erstellt.
Alle Requests sind idempotent - bei Neustart wird der gleiche State erreicht.


--------------------------------------------------------------------------------
1.1 PROJECT ERSTELLEN
--------------------------------------------------------------------------------

PUT /vfp/projects/proj_01HXYZ123456789ABCDEF/meta.json HTTP/1.1
Host: api.synth.local
Content-Type: application/json
X-Vfp-Message: Initialize project

{
  "id": "proj_01HXYZ123456789ABCDEF",
  "name": "Example Synth Project",
  "description": "A demonstration project showing the synth-protocol XML structure",

  "settings": {

PHASE 2: LIVE EVENTS (WebSocket)
================================================================================

Nach dem initialen Setup verbindet sich der Client per WebSocket
für Realtime-Updates.


--------------------------------------------------------------------------------
2.1 WEBSOCKET VERBINDUNG
--------------------------------------------------------------------------------

Client connects to: ws://api.synth.local/vfp/realtime

Server:
{
  "op": "CONNECTED",
  "payload": {
    "tick": 20,
    "branch": "main",
    "projectId": "proj_01HXYZ123456789ABCDEF"
  }
}


--------------------------------------------------------------------------------
2.2 WATCH - Scene Nodes abonnieren
--------------------------------------------------------------------------------

Client:
{
  "id": "req-001",
  "op": "WATCH",
  "payload": {
    "patterns": ["/projects/proj_01HXYZ123456789ABCDEF/nodes/*"],
    "initial": true,
    "from_tick": 0
  }
}

Server:
{
  "id": "req-001",
  "op": "WATCH_OK",
  "payload": {
    "subscription_id": "sub_nodes_001",
    "tick": 20,
    "matched": 5
  }
}

Server (Initial State):
{
  "op": "DELTA",
  "payload": {
    "tick": 20,
    "nodes": [
      { "path": "/nodes/scene_main", "op": "snapshot", "data": {"name":"Main Scene","nodeType":"CLUSTER_NODE_TYPE_SCENE"} },
      { "path": "/nodes/folder_docs", "op": "snapshot", "data": {"name":"Documentation","parentId":"scene_main"} },

ZUSAMMENFASSUNG
================================================================================

VFP REST Mapping fuer Synth Projekte:

  /vfp/projects/{projectId}/
    meta.json                     Project Metadata
    tags/{tagId}.json             Tags
    nodes/{nodeId}.json           ClusterNodes (Scene, Folder, Document)
    components/{compId}.json      Components (ECS Data)
    assets/{assetId}/
      meta.json                   Asset Metadata
      data                        Asset Binary

HTTP Verben:
  GET       Lesen
  PUT       Erstellen/Update
  DELETE    Loeschen
  POST      Actions (_commit, _diff, _batch)

WebSocket:
  WATCH     Aenderungen abonnieren
  PUSH      Schnelle Updates (Client Prediction)
  DELTA     Server Broadcasts
  UNWATCH   Subscription beenden

Tick System:
  - Jede Aenderung erhoet den Tick
  - ETags fuer Optimistic Locking
  - Commits gruppieren Aenderungen
