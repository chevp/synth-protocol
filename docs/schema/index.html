Synth Protocol - XML Schemas

This page provides access to the XML Schema Definitions (XSD) for the Synth Protocol. All Synth document types share a single unified schema with one <synth> root element.

Unified Schema

Every .synth.xml document uses the same root element and namespace. The first child element of <synth> selects the document type (project, scene, component, and so on).

  • synth.xsd (v1.0)
    Namespace: https://chevp.github.io/synth-protocol/schema/synth/1.0

    The single, unified schema for all Synth document types. Validates the <synth> root and every supported document type below.

Document Types

These are the child elements permitted directly under <synth>:

ElementPurpose
<project>Project configuration: metadata, servers, security, asset mounts, resources, settings.
<scene>Scene definition: entities, transforms, component references, lights, camera.
<component>Reusable component definition: metadata, mesh reference, properties.
<routes>Route/endpoint mappings for the runtime.
<runtime>Runtime configuration.
<runtime-renderer>Renderer-specific runtime configuration.
<runtime-logic>Logic-layer runtime configuration.
<game-project>Game project definition built on top of a project.
<asset-registry>Registry of assets, fragments, and components.
<extension>Extension container for domain-specific additions.
<shop-catalog>Shop / catalog definition (e.g. merchant inventories).

Elyrion Schema

  • elyrion.xsd (v1.0)
    Namespace: https://chevp.github.io/synth-protocol/schema/elyrion/1.0

    Schema for Elyrion package/scene descriptors: dependencies, remote sources, assets, and asset variants.

Usage Examples

Project Definition

<?xml version="1.0" encoding="UTF-8"?>
<synth version="1.0" xmlns="https://chevp.github.io/synth-protocol/schema/synth/1.0">
    <project schema-version="1.0">
        <metadata id="my-game">
            <name>My Game</name>
            <version>0.1.0</version>
        </metadata>
        <settings>
            <setting key="defaultScene" value="plaza"/>
        </settings>
    </project>
</synth>

Scene Definition

<?xml version="1.0" encoding="UTF-8"?>
<synth version="1.0" xmlns="https://chevp.github.io/synth-protocol/schema/synth/1.0">
    <scene version="1.0" id="plaza-scene">
        <metadata>
            <name>Town Plaza</name>
        </metadata>
        <entities>
            <entity id="player_spawn" name="Player Spawn Point">
                <component ref="components/player/spawn-point.synth.xml"/>
                <transform>
                    <position x="0" y="0.1" z="10"/>
                </transform>
            </entity>
        </entities>
    </scene>
</synth>

Component Definition

<?xml version="1.0" encoding="UTF-8"?>
<synth version="1.0" xmlns="https://chevp.github.io/synth-protocol/schema/synth/1.0">
    <component id="npc-merchant">
        <metadata>
            <name>Merchant NPC</name>
            <type>npc</type>
        </metadata>
        <mesh ref="synth://assets/models/character_merchant"/>
        <properties>
            <property name="interactable" type="bool" value="true"/>
        </properties>
    </component>
</synth>

More complete, ready-to-run examples live in the examples/ directory.

Local Development

For offline editing and IDE validation, use the XML catalog to resolve schema URLs to local files. See catalog.xml. It maps the synth/1.0 and elyrion/1.0 namespaces to their local .xsd files, and also records legacy and roadmap namespaces for reference.

Note: Earlier releases exposed separate component.xsd, scene.xsd, and project.xsd files with distinct root elements (<synthComponent>, <synthScene>, …). These have been consolidated into the single synth.xsd above, and all documents now share the <synth> root.
